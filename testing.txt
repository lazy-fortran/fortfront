Plan: Remove Remaining Stack Risks and Prove Windows Pipe Stability

Goal
- Ensure fortfront runs reliably on Windows with stdin piping (cmd/type, PowerShell) without increasing stack reserve, by eliminating stack-heavy code paths and validating with targeted tests.

Context (what’s already done)
- Replaced recursive standardizer traversal with an iterative driver (heap-backed work stack). Local tests (RUN_SYSTEM_TESTS=1) pass.
- Large stack locals audited; moved suspicious ones to allocatables.
- Windows still crashes immediately for CLI “normal” path under CI; fortfront --version works. Trace suggests failure occurs before our program body log emits in that invocation mode.
- Converted the CST-to-AST converter, constant-folding walker, and undefined-variable checker to use explicit stacks. Linux `RUN_SYSTEM_TESTS=1 fpm test` passes with very small `ulimit -s`, confirming those paths no longer rely on deep recursion.
- Updated the scope manager to overwrite existing bindings so iterative inference can refine symbol types without leaving stale type variables in the environment.
- Windows CI run 17760082998 (job 50516090458) still fails: `fortfront.exe` exits with `0xC00000FD` before emitting CLI trace entries. The remaining stack depth originates from `semantic_analyzer%infer_type` and the recursive helper calls it makes while walking child expression nodes.

Current status (2025-09-16)
- Latest Windows rerun (Actions run 17760082998) reaches `fpm test` and dies during the CLI integration tests. Traces are empty, aligning with an overflow prior to the first CLI log call.
- Local CLI integration test (`RUN_SYSTEM_TESTS=1 fpm test test_cli_integration`) now fails gracefully on Linux (exit code 1) but does not crash, providing a safe harness for regression checks while we rework inference.

Immediate plan
- [x] Refactor `semantic_analyzer%infer_type` into an iterative traversal. Approach: introduce an explicit work stack (node index + state flag) so child expressions are processed before the parent computes its type, mirroring the pattern used in `constant_transformation`. Ensure helper routines (`infer_binary_op`, `infer_function_call`, `infer_array_literal`, etc.) no longer call back into `ctx%infer` recursively; instead they should consume previously inferred child types or push additional work items as needed.
- [x] After the refactor, stress-test locally with `ulimit -s 8` and `RUN_SYSTEM_TESTS=1 fpm test` (plus the focused CLI integration test) to confirm absence of stack overflow. (Note: compiler crashes under 8 KiB; verified successfully at 64 KiB.)
- [ ] Once local tests pass, rerun GitHub Actions to verify the Windows job completes. Capture and review the CLI trace to ensure it now reaches the transformation phase.

Follow-up tasks
- Audit remaining semantic walkers (e.g., `process_forall_node_body`) for residual recursion and convert any deep call chains to iterative forms if CI still shows stack pressure.
- Re-enable Windows CLI traces (remove temporary stderr instrumentation if added) after the overflow is resolved.

High-level strategy
1) Eliminate remaining recursion on hot CLI path (parser + traversal + select semantic walkers), even if typical depths are small on Linux.
2) Prove absence of large automatic stack objects on all modules imported by the CLI path.
3) Add minimal, opt-in deep instrumentation to capture earliest call sites on Windows (kept behind env toggles and removed post-fix if needed).
4) Expand Windows pipe tests to cover cmd/type and PowerShell echo piping, CRLF/LF inputs, and large-but-reasonable inputs.
5) Validate performance is unchanged or improved; no functional regressions.

Detailed work plan

A) Parser (expressions) — iterative, no recursion
- Replace recursive descent layers with precedence-climbing / Pratt parser:
  - parse_logical_eqv/or/and: keep iterative loops (already iterative)
  - parse_comparison/concatenation/term/factor: keep iterative loops (already iterative)
  - parse_power: remove right-associative recursion using explicit operator stack
  - parse_unary: implement iterative consume of prefix operators
  - parse_primary: keep non-recursive branch; ensure calls that could recurse (e.g., nested primaries) are handled iteratively
- Deliverables: src/parser/parser_expressions.f90 rewritten sections + focused tests under test/parser/… for exponent nesting, unary chains, mixed precedence.

B) AST traversal utilities — iterative visitors
- Add iterative traverse_ast_* helpers using explicit stacks (SoA for indices and flags):
  - traverse_preorder_iter, traverse_postorder_iter
  - Switch CLI path usages to the iterative variants (keep recursive versions available for now, then phase out).
- Deliverables: src/ast/traversal/* new functions; adapt callers on CLI pipeline; tests under test/ast/ to exercise deep trees.

C) Semantic passes — remove recursion on CLI hot path
- Inspect and flatten any recursive walkers reachable in CLI minimal inputs:
  - infer_type (hot expression cases)
  - undefined variable checker traversal
  - constant folding walkers
- Replace with explicit work stacks where needed.
- Deliverables: targeted changes in src/semantic/* with unit tests (test/semantic/) for deep nesting inputs.

D) Audit for large automatic locals / early initializers
- Scan modules imported by app/fortfront.f90 for fixed-size locals >= 4 KiB or large arrays.
- Replace with allocatables or small fixed buffers + chunked processing.
- Verify no heavy module-level initializers run on program start.

E) Windows pipe test matrix & diagnostics
- Expand system tests to run:
  - cmd /C type file | fortfront
  - PowerShell Get-Content file | fortfront
  - echo "…" | fortfront (short and long lines; LF and CRLF)
- Capture earliest stderr lines (ultra-early trace) and exit codes per case.
- Add a large (but bounded) input case to confirm stability.

F) Performance & regression validation
- Measure transform throughput on representative inputs before/after parser changes.
- Ensure no material slowdowns.
- Keep behavior identical: all existing tests green; no formatting drift.

Milestones & checkpoints
M1) Parser iterative refactor merged; parser tests pass; CLI tests pass locally.
M2) Iterative traversal utilities wired on CLI path; tests pass locally.
M3) Semantic walkers flattened where needed; tests pass locally.
M4) Windows CI green for file and pipe tests; traces removed or guarded.
M5) Perf sanity: equal or better throughput on transform-heavy tests.

Risk management
- Parser refactor is the largest logical change; mitigate with targeted parser tests for associativity/precedence/unary chains.
- Keep iterative and recursive traversal side-by-side until test parity is proven; then remove old code.
- Avoid broad churn: change only hot-path modules first; defer non-CLI code.

Success criteria
- Windows CI: all CLI system tests (including pipes) pass without increasing stack reserve.
- No regressions on Linux/Mac; tests remain green.
- Perf is on par or improved.

Notes
- If a specific Windows RTL quirk remains after refactors, we will add a minimal Windows-only fallback to read stdin via a small fixed buffer loop (already present) and confirm no hidden recursion occurs before our entry point.
